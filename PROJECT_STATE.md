## 3. Реализованный функционал

### USB / устройство
- Сканирование USB через `idevice_event_subscribe` + `g_idle_add` (ADD → `start_scan`, REMOVE → удаление из `device_store`).
- Поддержка горячего подключения: подключение/отключение устройства обновляет UI автоматически.
- Информация об устройстве: модель, версия iOS, серийный номер, UDID, батарея, используется/свободно накопления.
- Блокировка импорта, если приложение «Музыка» открыто на устройстве (прямая правка БД может быть перезаписана).

### Медиатека (музыка)
- Чтение треков из `MediaLibrary.sqlitedb` устройства (через AFC загрузка БД во временный файл, затем чтение через вшитый SQLite).
- Живой поиск и сортировка (по названию, исполнителю, альбому, длительности).
- Импорт аудиофайлов с встроенными обложками (TagLib).
- Экспорт треков с устройства на компьютер.
- Удаление треков из медиатеки.

### Обложки artwork (главный прорыв)
- Формула пути подтверждена на **377 реальных строках** artwork на живом устройстве:
  `Originals/<sha1(строка_токена)[0:2]>/<sha1(строка_токена)[2:40]>`
  — бакет = первые 2 символа хеша, имя файла = остальные 38 символов (вместе полный SHA-1).
- Токен берётся из строки (`sha1("481")`), а не из байтов картинки (раньше ошибочно хешировали байты → «Image did not exist at URL»).
- `interest_data` пишется как BLOB-литерал `X'…'` (как у всех 384 реальных строк).
- Наследование токена альбома: если у альбома есть токен src300, трек получает его же (меньше файлов).
- Дедуп обложек по содержимому убран — путь производен от токена.
- Самоисправляющая миграция `medialib_fix_artwork_paths()`: при импорте чинит `relative_path` старых токенов (481/482) по формуле.

### Безопасность / надёжность
- Бэкап `MediaLibrary.sqlitedb` перед каждой записью в `~/.local/share/apple-devices/backups/`.
- Логи отладки внизу главного окна (Debug Logs).
- Транзакции с SAVEPOINT при записи медиатеки.

### Локализация и интерфейс
- Двуязычный UI: русский / английский (GNOME HIG, Adwaita, символические иконки).
- Настройки: `~/.config/apple-devices/settings.ini` (язык и т.п.).
- Журнал отладки внизу окна.

## 4. Известные ограничения и баги

| # | Описание | Статус |
|---|----------|--------|
| 1 | **Плейлисты не реализованы** — схема `container`/`container_item` снята с живой БД, но редактирование не начато. | План (после Шага 1) |

| 8 | Нет переключателя «Скрывать личные данные» для Serial Number / UDID в Обзоре. | Шаг 2 |

## 5. Принятые архитектурные решения

1. **Прямая запись в `MediaLibrary.sqlitedb` вместо MobileSync.** Протокол Apple MobileSync закрыт; устройство открыто отдаёт AFC + SQLite, и прямая правка БД — единственный работающий способ без реверс-инжиниринга закрытого протокола.
2. **Статическая вставка sqlite3 amalgamation.** Избавляет от зависимости от версии системного sqlite3 и гарантирует одинаковое поведение SQL на разных дистрибутивах.
3. **Путь обложки = SHA-1 от строки токена** (не от байтов картинки). Подтверждено логом «Музыки» и 377 реальными строками artwork. Обратная совместимость обеспечивается самоисправляющей миграцией.
4. **Наследование токена альбома.** Уменьшает число файлов на устройстве и работает для треков без встроенной обложки.
5. **Бэкап перед каждой записью.** Критично, так как база правится напрямую без транзакций на уровне устройства.
6. **«Музыку» закрывать перед импортом.** Открытое приложение на iPhone может перезаписать изменения в БД.
7. **Настройки в `~/.config/apple-devices/settings.ini`**, бэкапы в `~/.local/share/apple-devices/backups/` — не переименовывали, чтобы сохранить пользовательские настройки.

#### Шаг 3 — Диаграмма накопителя с категориями (ЗАВЕРШЁН, коммит `7eeefab`)

Исследование (read-only зонд AFC на живом устройстве, ~12 с на полный обход):
- Размеры категорий iOS не отдаёт ни через lockdown (`ideviceinfo` — только
  `PartitionType`), ни через `afc_get_device_info` (только `FSTotalBytes`,
  `FSFreeBytes`, `FSBlockSize`).
- Но каталоги медиа-раздела доступны через AFC: `/iTunes_Control/Music`
  (1,8 ГБ), `/DCIM` + `/PhotoData` + `/MediaAnalysis` (925 МБ вместе),
  `Books`, `Downloads` и др. Итого измеряемо ~2,9 ГБ из 40 ГБ занятых —
  остальное (приложения, система) через AFC недоступно в принципе.

Реализация:
- `afcUtils`: `afcDirSize()` — рекурсивный размер каталога через AFC
  (только чтение, ограничение глубины, паттерн как у `afcCollectAudio`).
- `application.c`: фоновый GTask (`storageScanThread`/`onStorageScanFinished`)
  измеряет категории «Музыка» и «Фото» при выборе устройства; таблица
  `STORAGE_CATS` (корни AFC) + `STORAGE_CAT_META` (подпись/цвет) — новая
  категория добавляется одной строкой в каждую таблицу; G_STATIC_ASSERT
  следит за согласованностью. Устаревший результат (устройство сменилось)
  отбрасывается; при неудаче подключения — запись в лог.
- Отрисовка `storageBarDraw`: сегменты категорий поверх «Занято» (цвета
  #f66151 Музыка, #dc8add Фото), остаток занятого — «Прочее» (#3584e4),
  затем «Свободно»; подпись сегмента рисуется, только если влезает
  (drawSegmentLabel уже умел). Пока измерение идёт — «Занято/Свободно».
- Tooltip при наведении: GtkEventControllerMotion + `storageSegAt()`
  (hit-test по доле ширины, с тем же зажимом, что у отрисовки) +
  `storageSegTip()` — подпись и точный размер через
  `g_format_size_full(G_FORMAT_SIZE_LONG_FORMAT)` (с числом байт).
- Демо-данные убраны: `DEMO_TOTAL_GB`/`DEMO_USED_PCT` и поле `storage_demo`
  удалены; если `total == 0` или `used > total` — подпись «Данные о
  накопителе недоступны», в шапке подзаголовок без размеров.
- На живом устройстве: Музыка — 1,8 ГБ (1 758 158 623 байта), Фото —
  925,2 МБ (925 162 282 байта); сборка без предупреждений из своих файлов.
- Известное ограничение: категории перемеряются при каждом выборе
  устройства (~12 с AFC-обхода); при частых ресканах от событий USB —
  повторные измерения. Возможная оптимизация на будущее: кэш по UDID

#### Фикс: плашка «Подсчёт категорий…» на диаграмме накопителя (коммит `c3a1ca8`)

Баг (скриншот пользователя): на пару секунд после выбора устройства на полосе
появлялся артефакт-«плашка», пока не подгружались категории.

Причина: в промежуточном состоянии (`storage_n_cats == 0`) в `storageBarDraw`
срабатывали ОБЕ ветки подписей — «Прочее · …» (условие `rest > 0` истинно и
без категорий, `rest` = всё занятое) и «Занято · …» — две строки рисовались
в одной точке `usedW/2`, наложение давало артефакт.

Исправление:
- `storageBarDraw`: при `storage_measuring && storage_n_cats == 0` —
  нейтральная плашка «Подсчёт категорий…» (новая tr-строка
  «Counting categories…») вместо преждевременных «Занято/Свободно»;
  подпись «Прочее» рисуется только при `storage_n_cats > 0`, «Занято» —
  только при `storage_n_cats == 0` (двойная отрисовка устранена).
- `AppleApplication`: поля `storage_measuring` (идёт подсчёт) и
  `storage_scan_seq` (счётчик запусков).
- `startStorageScan`: ставит `measuring = TRUE`, наращивает `seq`, номер
  запуска пишется в `StorageScanCtx.seq`.
- `onStorageScanFinished`: устаревший запуск (пересканирование при смене
  устройства) отбрасывается сравнением `seq` ДО касания флагов; флаг
  `measuring` сбрасывается и при неудаче подсчёта — бар честно
  возвращается к «Занято/Свободно».
- `uiWidgets`: при снятии выбора устройства сбрасывается и `measuring`.

Сборка без предупреждений; smoke-тест на живом устройстве чистый
(Музыка 1,8 ГБ / 1 758 158 623 байта, Фото 925,2 МБ / 925 174 642 байта).
