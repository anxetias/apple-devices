# 03 — Методика REA (декомпиляторы, динамика)

Инструмент: MCP-сервер **REA** (инструменты вызываются через Code Mode: `execute` → `tools.rea.*`).
Перед первым вызовом конкретного инструмента — `search(query)` для точного имени/сигнатуры.

## Статика (декомпиляторы)

1. `open_binary(path)` — открыть нативную цель (Mach-O). Затем инструменты:
   - `binary_overview` — класс/срезы/символы;
   - поиск функций/строк/имен (strings-секция u) и вызовов;
   - `analyze_function` на выбранной функции — summary-first, полный докер по `parent_evidence_id`;
   - псевдокод/дизасм по функциям — направлять на конкретные символы (`AMDevice...`, `MuxConnect`,
     `AFCPacketRead`, имена surviving селекторов Objective-C: `[... startService:]`).
2. Порядок целей — см. `docs/02-artifacts.md`. Начинаем с `usbmuxd` (он маленький), потом MobileDevice.
3. Символы: у системных бинарников Objective-C классы (и секция `__objc_methname`) обычно живые —
  strstr по `__objc_methname` даёт именованную карту API, к которой я пишу проверки.

## Динамика (рантайм-наблюдение — решает то, что статика не даёт)

1. **Frida-хуки на живом usbmuxd / MobileDevice.framework** (spawn/attach через `start_frida_...`),
   хуки на `SSLAccept`/`SSLHandshake*`/`AMDeviceConnect`/`AMDeviceSecTrustEvaluate`,
   `lockdownd`'ы и т.д.; ловим реальные plist-сообщения → пишем в evidence дампы.
2. **gdb/rizin-сессии** для новых/стартап-/state-машин (mobilesync device-ная сторона удобнее через
   дамп в IPSW, но хостовая часть тоже интересна).
3. Логирование live-обмена: перехват `CFReadStream`/`NSStream` и сессий через mux.

## Правила выбора «какая цель для какого знания»

| Вопрос по протоколу | Где искать |
|---|---|
| Разовые формат сообщений (mux/plist/afc/backup/restore) | статика соответствующего клиента (usbmuxd / MobileDevice / CoreService) + динамика через хуки демонов |
| Ограничения/правила (путиMedia, права AFC) | устройство: lockdownd/afc демон из IPSW + живые пробы через наш же код |
| Последовательность операций синка музыки | динамика AppleMobileSync/MDHelper + Music.app = «звонки» между ними |
| Таблица сервисов конкретной iOS | lockdownd из IPSW (`segedit -extract __TEXT __services`) |

## Лидгер (реестр фактов)

Каждая находка: файл `docs/evidence/E##.md`, формат:

```md
# E## — <короткое имя>
Вопрос: ...
Источники: {"реальный путь/функция/адрес", Evidence-ID REA}
Наблюдение: ... (как есть, с адресами/строками, без интерпритации)
Вывод (что реализуем в C): ...
Осталось непонятным: ...
```

Принцип: **наблюдение ≠ вывод**. В вывод — только то, что прямо следует из наблюдения.
