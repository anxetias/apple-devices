## 0. Постановка

Официальный клиент «Устройства Apple» (Apple Devices, Microsoft Store) в Windows VM
импортирует музыку вместо iTunes. Цель — понять:
1) нужна ли сеть/серверы Apple при импорте одного трека;
2) где генерируется Grappa-токен/ATC-сессия (какой процесс → DLL → функции → ключевой материал);
3) делегирует ли 3uTools часть работы AMDS (гипотеза, без захода в замороженную ветку);
4) воспроизводим ли путь на Linux/libimobiledevice без сервера 3uTools.

Оборудование VM: Apple Devices (Store), сервис AppleMobileDeviceService (RUNNING),
Python 3 + frida-tools, Wireshark, ProcMon, x64dbg/IDA Free (по необходимости).

## 1. Гипотезы (проверяемые, фальсифицируемые)

- **H1 (сеть)**: официальный импорт трека полностью локальный (USB-канал; никаких
  запросов к серверам Apple/третьим лицам в окне импорта). Проверка: S1 Wireshark -
  фоновый шум отдельно, окно импорта отдельно; S2 — импорт при выключенной сети в VM.
  Фальсификация: в окне импорта видны TLS-SNI/PROXY/dns к Apple (gs.apple.com,
  itunes.apple.com, mx*, init.itunes.apple.com, appstoreb*, …) с нагрузкой/ответом,
  без которых синхронизация не идёт.
- **H2 (диалог)**: официальный клиент разговаривает с устройством через lockdown-сервис
  (usbmux), форма диалога ATC-типа: RequestingSync → ReadyForSync (содержит Grappa
  устройства) → FinishedSyncingMetadata → AssetManifest → FileProgress/FileComplete →
  SyncFinished (из косвенных наблюдений из прошлой задачи). Фальсификация: другие
  команды/другой фрейминг (например, только XML, или другой порядок, или другой
  транспорт — HTTP-чат через 27015/IPC/pipe).
- **H3 (`.cig` не нужен)**: официальная декларация синхрониза не требует подряд
  серверно-подписанного файла `.cig` (или подпись генерится локально в AMDS).
  Проверка: полный захват трафика на 27015 (frida + Wireshark) — что реально льётся в
  `/iTunes_Control/Sync/**` и что устройство соглашается принять.
- **H4 (Grappa локально в Windows)**: hostGrappa генерится локально (AMDS/Apple Devices),
  без Apple-серверов. Проверка: frida/ProcMon локализуют код; диссасм: какой
  модуль и какие импорты (bcrypt/ncrypt/coreCrypto).
- **H5 (3uTools частично сидит на AMDS)**: открытый вопрос, отложен (S5).
- **H6 (Linux-путь)**: по итогам пп. 1–4 — можно/нельзя импортировать на Linux без
  сервера 3uTools через официальный протокол.

## 2. Сценарии (подробности выполнения — `VM_TASKS.md`)

- **S0**: пред-снимок устройства с host (до проброса в VM) — agent, AFC read-only.
- **S1**: импорт 1 MP3 в VM при включённой сети; одновременно — Wireshark (baseline +
  окно импорта отдельными pcapng), ProcMon (фильтр Apple*), frida (run_hooks.py).
  После — vm_afc_pull.py внутри VM или возврат девайса на host для after-снимка.
- **S2**: то же самое при отключённой сети в VM (сетевой адаптер VM выключен).
  Итог: импорт прошёл/нет; что.xlabel; baseline шум лог; KL.
- **S3** (опционально чуть позже): сравнение со старым iTunes — только для
  понимания изменений протокола, не как основной клиент.
- **S5** (отложено): Windows-перехват 3uTools для проверки H5. Не начинать без отдельного решения.
